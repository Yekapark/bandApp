# Flyway 마이그레이션

- 파일명 규칙: `V{순번}__{설명}.sql` (예: `V1__auth.sql`, `V2__band.sql`)
- 스키마 변경은 반드시 이 디렉터리의 마이그레이션으로만 한다 (`spring.jpa.hibernate.ddl-auto: validate`)
- Phase 0에는 도메인 테이블이 없다. 첫 마이그레이션은 Phase 1(인증)에서 추가된다.

## V19 — 반복 회차의 원래 슬롯

`original_start_at`을 추가하고, 반복 회차의 중복 방지 인덱스를 실제 시각에서 원래 슬롯으로
옮긴다. 기존 행은 현재 `start_at`을 복사한다. 일정 시각·상태·정산·납부 이력은 바꾸지 않는다.
이미 옮긴 기존 회차의 원래 날짜는 저장된 이력이 없으므로 자동 복원을 하지 않는다.

V19는 반복 회차에 원래 슬롯이 반드시 있어야 한다는 제약도 추가한다. 적용 후에는 이 필드를
채우지 않는 V18 이전 애플리케이션으로 단순히 이미지만 되돌리면 반복 회차 생성이 실패한다.
새 스키마를 지원하는 코드와 함께 적용한다. 실제 운영 적용·과거 이력 보정은 별도 작업이다.

`RecurringOriginalSlotMigrationTest`가 별도 테스트 스키마에 V18 데이터를 만든 뒤 V19로
올려 일정·정산 보존, 단발 일정의 null, 실제 시각 겹침 허용과 원래 슬롯 중복 차단을 검증한다.
