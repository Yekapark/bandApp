## 진행 현황과 사용법

일부라도 실제 진행 **146/208=70.2%**, 모든 조건 실제 확인 **51/208=24.5%**. 완료가 남은 항목 **157개(93+2+62)**다. (10/5 클로드: OPS-02·OPS-11·OPS-16 ⬜→✅, 아래 "클로드 확인 완료" 8개 ⬜/🟡→✅)
자동 테스트만 통과한 항목을 실기기·운영 실행 완료로 세지 않는다 — **단, 아래 "🤖 클로드 확인 완료" 표시 항목은 예외**(사용자 지시 2026-10-05). +35 확인을 +36 통과로 옮기지 않는다.
완료율은 복합 시나리오 하나의 모든 명시 조건을 확인했을 때 올라가므로 시험 시간 비율과 다르다.

각 항목을 한 번만 정의했다. **시험 → 현재 판정 → 이번에 할 일 → 준비 조건 → 근거** 순서로 읽는다.
체크는 해당 항목의 모든 조건을 실제로 확인했을 때만 한다. 일부 조건은 현재 판정을 갱신하고 남은 조건을 줄인다.
같은 흐름의 다른 ID는 아래 ‘함께 실행’으로 연결했으며 조건을 삭제하지 않았다.
새 기록에는 날짜·설치 versionCode·기기·실행 경로·응답/화면·정리 결과를 남긴다.
비밀번호·인증번호·JWT·구매 토큰·서명 URL은 기록하지 않는다.

## 실행 규칙 — 한 항목씩 마무리한다 (2026-10-05 사용자 지시)

**같은 실수 방지:** POST-03에서 이모지60개만 시험하고 같은 화면에서 가능한 긴 한글·여러 줄·빈 입력을 남긴 채 다른 항목으로 넘어갔다. 또 정기 폼 연도 표시를 요금제 BILL-20과 잘못 연결했다. 현재 규칙은 이 분산 실행·잘못된 완료 연결을 막기 위한 것이며 문서 변경만으로 시험을 통과시키지 않는다.

1. 한 ID를 고르면 `시험`의 조건을 먼저 펼쳐 확인하고, **실행 가능한 조건을 모두 시험 → 조건별 결과·정리 기록 → 전체 판정 갱신 → 다음 ID** 순서로 진행한다. 특정 수정 조건만 확인하고 다른 실행 가능한 조건을 미루지 않는다.
2. 추가 기기·시간 대기·권한/준비물 부족 또는 선행 결함 때문에 실행할 수 없는 조건만 남겨 둘 수 있다. 무엇이 막혔는지·확인한 범위·재개 조건을 명시한다. 사용자 중지·연결 끊김은 마지막 진행 ID와 다음 조건을 남긴다.
3. 좁은 회귀는 **“이 조건만 완료”**, ID 전체는 **“모든 명시 조건 완료”**로 구분한다. 정기 폼/요금제, 앱내 알림/OS 푸시, 자동 테스트/실제 설치본처럼 다른 범위를 같은 증거로 완료 처리하지 않는다.
4. 결함은 이 문서의 **「현재 결함·+36 지정 회귀」 표**에 모으고 발견 번호·출시 번호·관련 ID·최신 실제 상태·상세 이력 위치를 연결한다. **클로드 등 수정 담당자는 이 표부터 읽는다.** 상세 실행은 QA_CHECKLIST, 출시 상태는 LAUNCH_REVIEW §1·영역표 양쪽에 기록한다. 수정된 설치본으로 재검증하기 전 실기기 완료로 바꾸지 않는다.
5. 캡처는 TEMP에 만들고 화면 확인 직후 PC·폰 임시 파일을 지운다. 화면 덤프·인증 임시 파일·일회용 계정/밴드도 정리 결과를 확인한다. 원본 갤러리·기존 계정/밴드 보존. 영구 유지 데이터는 별도 목적·정리 시점을 기록한다.
6. 기본 시험 계정은 사용자가 제공한 `demo.leader@bandule.com`(리더), `demo.guitar@bandule.com`·`demo.drum@bandule.com`(멤버)이다. 세 계정의 지정 테스트 밴드 역할을 사용하되 실제 화면/API로 역할을 확인한다. 사용자 본인 계정은 일반 시험·삭제 대상으로 사용하지 않는다. 비밀번호는 이 문서나 저장소에 적지 않는다. 가입/탈퇴 시험 등은 새 일회용 계정으로 한다.

### 출시 문서 대조에서 보강·주의한 점

- **B18:** 보류 중 유료 혜택 제한과 결제 보류 표시는 별개다. ‘그냥 FREE’로 재결제를 허용하는 옛 기대는 폐기. 살아 있는 구독이 있으면 다른 상품/계정의 두 번째 구매를 거절하고 환불 확인.
- **B4·QA-R03:** 밴드 두 개 각각 결제→둘 다 PREMIUM. 같은 Google 계정의 두 번째 밴드를 막는 예전 기대는 폐기. 여섯 번째 상품 제한은 별도.
- **B19·B20:** 몫 금액이 같으면 납부 유지, 바뀌면 체크 해제·알림. 이탈/불참 납부 기록과 납부 금액 보존. SET-05의 예전 단순 ‘납부 유지’와 구분.
- **B22:** purchase_token 중복 금지 V22 적용/제약 실제 확인을 OPS-01에 추가 대조 조건으로 포함. 새 시험을 실행했다는 뜻이 아니다.
- **U23:** 링크 처리 뒤 재로그인 홈·합류 화면 한 겹 조건을 BAND-06 잔여에 명시.
- **U34:** TalkBack 수정9곳(지우기·정기 일정 삭제 포함)을 UI-04 범위에 명시. 특정 접근성 트리 이름 확인을 실제 음성 통과로 대신하지 않는다.
- **U35:** 글/일정/정기/방 작성뿐 아니라 저장 중 화면 종료·목록 갱신까지 UI-06의 지연 경합으로 남김.
- **G2:** 합쳐진 원격 브랜치 정리는 QA가 아닌 별도 출시 작업이다. 사용자 예약 중지 요청 상태에서 삭제 스크립트를 실행하지 않는다.
- **G4/G5·U3/U15/U16:** 도구·빌드·훅의 기존 완료/하지 않음 결정은 유지, 새 기기 QA 통과로 세지 않는다.
- **U13:** 테스터 해결 보고는 보존한다. S25+ 기기가 없어 UI-09 해당 기기 회귀는 미실행.
- **§9 출시 후로 정한 항목:** 9·10·15·16·29·30·34·35·37·42·47·48·49·52·53·54·60은 이번 목록 정리만으로 출시 전 작업으로 바꾸지 않는다. U36은 출시 후 후보, 결정46은 실제 결제 확인 뒤 판단.
- **LAUNCH의 오래된 숫자/빌드 표현:** Q1의119/208·28/208, +34/+35 업로드 대기 표현은 당시 상태다. 이번 정리는 LAUNCH 파일을 수정하지 않으며 최신 QA 수치는 이 목록을 읽는다.
