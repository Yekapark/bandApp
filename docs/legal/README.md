# 약관·개인정보처리방침 초안

> **이건 법률 문서가 아니라 "사실 정리"다.**
>
> 생성기나 표준 양식에 넣을 값을 코드에서 뽑아 정리한 것이다. 문구의 법적 효력은
> 검토받지 않았다. 그대로 게시하지 말고, 생성기에 넣거나 사람이 다듬은 뒤 올린다.

## 왜 이렇게 하나

남의 약관을 베끼면 **우리 앱이 실제로 하지 않는 일**이 들어간다. 개인정보처리방침은
사실과 다르면 그 자체가 위반이라, 어렵더라도 "우리가 진짜 뭘 하는지"에서 출발해야 한다.

여기 적힌 수집 항목·보관 기간은 전부 **코드에서 확인한 값**이다. 근거 파일을 함께 적어
뒀으니, 나중에 동작이 바뀌면 이 문서도 같이 고친다.

## 채워야 하는 것

코드에서 못 뽑는 값이다. `⟨⟩` 로 표시해 뒀다.

- 서비스 운영자 이름(개인 또는 사업자명)
- 문의받을 이메일 주소
- 개인정보 보호책임자 이름·연락처
- 사업자등록번호 (사업자로 운영한다면)
- 게시 예정 주소 — `bandule.com/privacy`, `bandule.com/terms`

## 문서를 고치면 버전도 올린다

`app.terms.version` / `app.terms.privacy-version`(기본 `2026-09-06`)은 **게시본의 시행일**이다.
회원가입 시 이 값으로 동의 기록을 남기므로, **문서를 고쳐 새로 게시하면 이 값도 함께 올린다.**
안 올리면 새 약관에 동의한 사람과 옛 약관에 동의한 사람이 구분되지 않는다.

> 기존 회원에게 다시 동의를 받는 화면은 아직 없다. 중요한 변경을 하게 되면 그때 만든다.

## 기능이 생기면 약관도 함께 고친다

**약속은 지킬 수 있는 만큼만 썼다.** 아래는 지금 못 하는 일이라 조항을 비워 둔 것이고,
기능이 생기면 약관을 먼저 고쳐야 한다.

| | 지금 | 생기면 |
|---|---|---|
| 결제 | 쿠폰 전환만 | 요금·결제 수단·환불 규정 (약관 제12조) |
| 계정 정지 | 기능 없음 | 정지 사유·기간·고지·이의 절차 (제14조). **근거 조항 없이는 정지할 수 없다** |
| 앱 내 공지 | 없음 | 약관 변경 통지 방법 (제3조) |
