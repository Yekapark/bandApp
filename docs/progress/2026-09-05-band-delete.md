# 밴드 삭제 — 밴드와 그 안의 모든 데이터 지우기

> 2026-09-05. 같은 날 앞선 작업은 [2026-09-05-plan-lifecycle-and-media-fix.md](2026-09-05-plan-lifecycle-and-media-fix.md).
> 이어서 할 일은 [NEXT.md](NEXT.md).

## 한 줄 요약

밴드장이 밴드를 삭제할 수 있게 했다. **경고를 보여주고, 밴드 이름을 정확히 입력해야만
지워지며, 실제로 전부 지워진다** — 사진·영상 파일까지 포함해서.

---

## 1. 왜 만들었나

지금까지 밴드를 없애는 방법이 없었다. "이 밴드에서 나가기"만 있어서, 마지막 멤버가
나가면 밴드가 **아무도 못 들어가는 빈 껍데기로 남았다**. 데이터는 그대로 남아 있는데
접근할 방법이 없는 상태다.

개인정보 관점에서도 문제다. 밴드를 정리하고 싶어도 올린 사진·영상이 계속 저장돼 있었다.

---

## 2. 무엇을 지우나

밴드 하나에 딸린 것을 **전부** 지운다.

| 지우는 것 | 설명 |
|---|---|
| 밴드 자체와 멤버 기록 | 나갔던 멤버의 과거 기록까지 |
| 합주 일정 · 정기 일정 규칙 | |
| 참석 응답 · 셋리스트 | |
| 정산 내역과 멤버별 몫 | |
| 게시글과 첨부 | |
| **저장소의 사진·영상 파일** | 실제 파일까지 지운다 |
| 그 게시글·사진에 대한 신고 | |
| 합주실 정보 | |
| 초대코드 | |
| 요금제와 쿠폰 사용 기록 | |
| 알림 이력 | 안 지우면 없어진 밴드의 알림이 계속 뜬다 |

**지우지 않는 것** — 밴드와 무관한 것들이다.

- **사람 차단 기록**: "이 사람을 차단"은 밴드가 아니라 사람에 대한 것이라 다른 밴드에서도
  유효해야 한다
- **사용자 계정·알림 설정·기기 등록**: 밴드를 지우는 것이지 탈퇴가 아니다
- **사람에 대한 신고**: 대상이 사라지지 않았으므로 남긴다

---

## 3. 실수로 지우는 걸 막는 장치

되돌릴 수 없는 동작이라 두 겹으로 막았다.

1. **밴드장만** 보이고 누를 수 있다. 일반 멤버에게는 버튼 자체가 없고, 혹시 요청을
   직접 보내더라도 서버가 거절한다.
2. **밴드 이름을 정확히 입력해야** 삭제 버튼이 활성화된다. 화면에 무엇이 지워지는지
   먼저 보여주고, 이름 칸이 비어 있거나 다르면 버튼이 눌리지 않는다. 서버에서도
   같은 검사를 한 번 더 한다.

계정 탈퇴가 비밀번호를 요구하는 것과 같은 계열의 방어다.

---

## 4. 순서가 왜 중요한가 (기술 배경)

**파일을 먼저 지우고, 데이터베이스를 나중에 지운다.**

반대로 하면 "어떤 파일을 지워야 하는지"를 적어둔 기록이 먼저 사라져서, 저장소에
아무도 못 찾는 파일이 영원히 남는다(돈이 계속 나간다). 그래서 파일 삭제가 실패하면
**데이터베이스는 아예 건드리지 않고 오류를 돌려준다.** 다시 누르면 된다.

파일은 하나씩이 아니라 밴드 폴더 통째로 지운다. 더 짧고, **기록이 이미 놓친 파일까지
같이 정리된다** — 예전에 삭제가 실패해서 떠돌던 파일도 이때 함께 사라진다.

데이터베이스 삭제는 전부 한 묶음이라, 중간에 하나라도 실패하면 전체가 취소된다.
**반쯤 지워진 밴드가 생기지 않는다.**

## 5. 직접 확인하는 법

```bash
cd C:\band\bandApp && docker compose up -d --build app
```

1. 테스트용 밴드를 만들고 **일정·정산·게시글·사진 첨부**를 하나씩 넣는다.
2. 설정 → 밴드 설정 → 맨 아래 **위험한 작업 → 밴드 삭제**.
3. 경고 문구가 뜨고, **이름을 안 넣으면 삭제 버튼이 회색**인지 확인한다.
4. 일부러 다른 이름을 넣어 본다 → 여전히 회색이어야 한다.
5. 정확한 이름을 넣고 삭제 → 홈으로 나가지고, 밴드 목록에서 사라져야 한다.

**기대 결과**: 데이터베이스에서 그 밴드 관련 행이 전부 없어지고, R2 버킷의
`bands/{밴드번호}/` 폴더가 비어 있다.

**주의**: 다른 사람 차단 기록은 남아 있어야 정상이다(밴드와 무관).

## 6. 검증 결과

| 검사 | 결과 |
|---|---|
| `./gradlew test` (백엔드 전체) | 통과 |
| `flutter test` (38개) | 통과 |
| `flutter analyze lib/` | 오류 0 |
| `python tools/check_cache_invalidation.py` | 누락 없음 |

새로 추가한 테스트 9가지:

- 밴드에 모든 종류의 데이터를 채워 넣고 지운 뒤 **15개 조회 전부 0인지** 확인
  (테이블을 빠뜨리면 여기서 걸린다)
- 저장소 파일이 폴더째 지워지는지
- 게시글·사진 신고는 지워지고 **사람 신고는 남는지**
- 차단 기록·계정이 남는지
- **다른 밴드는 멀쩡한지**
- 밴드장이 아니면 거절 / 외부인이면 거절 / 이름이 틀리면 거절(그리고 아무것도 안 지워짐)
- **저장소 삭제가 실패하면 데이터베이스가 하나도 안 지워지고, 다시 시도하면 성공하는지**

마지막 항목이 가장 중요하다 — 순서를 잘못 짜면 여기서 걸린다.

## 7. 알려진 이슈 / 판단이 필요했던 것

- **신고 기록을 지우는 게 맞나?** 원래 설계는 "신고는 대상보다 오래 남아야 한다"였다
  (지워진 글에 대한 신고도 운영자가 볼 수 있게). 하지만 밴드가 통째로 사라지면 대상
  콘텐츠가 없어져 처리 자체가 불가능하고, 지시자가 완전 삭제를 요구했으므로 지우기로
  했다. 운영상 신고 이력을 남기고 싶으면 이 부분만 빼면 된다.
- **복구 유예 기간이 없다.** 누르면 즉시, 완전히 사라진다. "30일 뒤 완전 삭제" 같은
  안전망은 지시자 요구("실제로 다 지워졌으면 좋겠어")에 따라 넣지 않았다.
- **삭제 API 가 DELETE 가 아니라 POST 다.** 확인용 이름을 본문으로 받아야 하는데,
  본문 있는 DELETE 는 클라이언트·프록시 지원이 고르지 않다. 계정 탈퇴
  (`POST /users/me/withdraw` + 비밀번호)와 같은 형태를 따랐다.
- **실기기 확인은 안 했다.** 자동 테스트만 통과한 상태다.
