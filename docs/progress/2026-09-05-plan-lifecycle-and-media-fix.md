# 요금제 수명주기(만료·1년·쿠폰) + 미디어 압축·용량 수정

> 2026-09-05. 앞선 작업은 [2026-09-05-brand-notifications-settlement-video.md](2026-09-05-brand-notifications-settlement-video.md).
> 이어서 할 일은 [NEXT.md](NEXT.md).

## 한 줄 요약

돈이 새던 구멍(기한 지나도 계속 PREMIUM)을 막고, 요금제를 밴드별 1년 구독으로 바꾸고,
맛보기 쿠폰을 붙였다. 그 과정에서 **영상 첨부가 그동안 아예 안 되고 있었다는 걸 발견해서 고쳤다.**

---

## 1. 영상 첨부가 깨져 있었다 (가장 중요)

### 무슨 일이었나

앞선 작업에서 영상 상한을 50MB → 200MB 로 올렸는데, **DB 쪽 제약만 안 올라갔다.**
서버 코드와 앱은 200MB 를 허용하는데 데이터베이스는 여전히 50MB 에서 막고 있었다.

업로드는 "먼저 자리를 만들고 → 그다음 파일을 올리는" 순서라, 50MB 를 넘는 영상은
**자리를 만드는 첫 단계에서 오류가 나 업로드를 시작조차 못 했다.** 앱이 720p 로 압축해도
5~6분 합주 영상은 90MB 안팎이라, 사실상 **영상 첨부 기능 전체가 동작하지 않는 상태**였다.

### 왜 여태 몰랐나

크기 제한을 검사하는 테스트는 있었지만 **데이터베이스를 거치지 않는 종류**여서
"코드가 정한 상한"만 확인했다. 코드와 DB 가 서로 다른 값을 갖고 있다는 건 볼 수 없었다.
실기기 확인 목록에 "영상 첨부"가 미완료로 남아 있었는데, 그게 바로 이 문제였다.

### 어떻게 고쳤나

DB 제약을 200MB 로 올렸고(`V12` 마이그레이션), **데이터베이스를 실제로 거치는 테스트**를
추가해서 100MB 영상이 통과하고 200MB 초과는 거부되는지 확인하게 했다. 같은 실수가
다시 나면 이 테스트가 잡는다.

---

## 2. 기한이 지나도 계속 PREMIUM 이던 문제

### 무슨 일이었나

밴드가 PREMIUM 을 시작하면 "언제까지"가 저장되지만, **그 날짜가 지나도 아무 일도 일어나지
않았다.** 한 번 PREMIUM 이 된 밴드는 영원히 PREMIUM 이었다. 돈이 걸린 문제다.

### 어떻게 고쳤나

매일 새벽 4시 45분에 도는 정리 작업을 새로 만들었다. 구독기간이 지난 밴드를 찾아
무료 요금제로 되돌리고, 그 밴드가 올린 사진·영상에는 **30일 유예**를 준다
(직접 해지했을 때와 똑같은 동작이라 사용자에게 "해지든 만료든 30일"로 설명이 단순하다).

### 직접 확인하는 법

앱을 띄운 뒤 만료 검사를 1분마다 돌게 바꿔서 본다:

```bash
cd C:\band\bandApp && docker compose up -d --build app
```

`.env` 에 `PLAN_EXPIRE_CRON=0 * * * * *` 를 넣고 위 명령으로 다시 띄운 다음, 데이터베이스에서
어떤 밴드의 구독 종료일을 어제로 바꾼다:

```sql
update band_plans set expires_at = now() - interval '1 day' where band_id = 1;
```

**기대 결과**: 1분 안에 그 밴드의 `tier` 가 `PREMIUM` → `FREE` 로 바뀌고,
그 밴드가 올린 사진·영상의 만료일이 30일 뒤로 찍힌다.

**안 되면**: 앱 로그에 `PREMIUM 구독기간 만료 강등 완료 count=N` 이 찍히는지 본다.
아무 로그도 없으면 `PLAN_EXPIRE_CRON` 이 적용 안 된 것이다(`up -d` 만 하면 옛 설정을
그대로 쓴다 — 반드시 `--build` 또는 `--force-recreate`).

## 3. 월 구독 → 밴드별 1년 구독

결제 주기를 1년으로 바꿨다. 설정값 변경이라 **앱 화면은 손대지 않았다** — 요금제 화면이
원래 "구독기간 연장", "구독기간 종료: {날짜}" 처럼 주기를 말하지 않는 문구를 쓰고 있었다.

미디어 유예기간 30일은 그대로다. 이건 구독 주기가 아니라 "해지 후 사진이 남아 있는 기간"이라
1년 구독과 무관하다.

### 왜 1년인가 (배경)

저장 비용은 시간이 갈수록 **쌓인다** — 밴드가 계속 영상을 올리면 보관해야 할 양이 매년 늘고,
그 비용은 밴드가 앱을 안 쓰게 되어도 사라지지 않는다. 한 번 받고 영원히 보관하는 구조는
시간이 지날수록 손해가 커진다. 1년 구독은 "비용이 매년 나가니 수익도 매년 받는" 형태라
이 문제가 생기지 않는다.

## 4. 맛보기 쿠폰

30일·60일·90일 같은 체험 기간을 주는 쿠폰을 만들었다.

- **이미 PREMIUM 인 밴드가 쓰면 남은 기간에 더해진다** — 일찍 쓴 사람이 손해 보지 않게.
- 같은 밴드는 같은 쿠폰을 **한 번만** 쓸 수 있다(데이터베이스가 막는다).
- 발급 장수를 정할 수 있고, 다 쓰이면 거절된다. 여러 밴드가 동시에 마지막 한 장을
  노려도 한 밴드만 성공한다.

### 쿠폰 발급하는 법

**앱에는 발급 화면이 없다.** 이 서비스에는 "앱 전체 관리자" 개념이 없어서(밴드장/멤버뿐)
관리자 로그인 체계를 새로 만들어야 하는데, 그건 쿠폰 자체보다 큰 일이다. 그래서
운영자가 데이터베이스에 직접 넣는다:

```sql
INSERT INTO plan_coupons (code, grant_days, max_uses, expires_at, created_at)
VALUES ('BANDULE7', 30, 100, now() + interval '90 days', now());
```

- `code` — 8자. 헷갈리는 글자(`0`/`O`, `1`/`I`)는 빼고 만드는 게 좋다
- `grant_days` — 며칠치 PREMIUM 을 줄지
- `max_uses` — 발급 장수. `NULL` 이면 무제한
- `expires_at` — 쿠폰을 쓸 수 있는 기한. `NULL` 이면 무기한

이미 뿌린 쿠폰을 막으려면: `update plan_coupons set revoked = true where code = 'BANDULE7';`

### 사용자가 쓰는 법

요금제 화면(밴드장만) → **쿠폰 코드 입력** → 코드 입력 → 사용.
소문자로 입력해도 되고 앞뒤 공백도 알아서 지운다.

**확인 포인트**: 무료 밴드에서 30일 쿠폰을 쓰면 PREMIUM 이 되고 종료일이 30일 뒤,
PREMIUM 밴드가 쓰면 기존 종료일에서 30일이 **더해진다**.

## 5. 사진도 압축해서 올린다

영상은 압축하고 있었는데 **사진은 안 하고 있었다.** 정확히는 화질만 조금 낮추고
크기(가로세로)는 원본 그대로 올라갔다 — 요즘 폰 사진이 4000×3000 이라 장당 2~4MB 였다.

긴 변을 2048픽셀로 줄이도록 했다. **장당 400~700KB 로 5배쯤 줄어든다.** 앱에서 보는
용도라 화질 차이는 느끼기 어렵다.

**확인 포인트**: 고화질 사진을 첨부해 올린 뒤 저장된 크기가 1MB 아래인지.

## 7. 아직 확인 안 된 것

**실기기 확인은 안 했다.** 자동 테스트만 통과한 상태다. 아래는 눈으로 봐야 한다:

- [ ] 5~6분 영상 첨부 — 위 §1 의 버그가 실제로 풀렸는지
- [ ] 고화질 사진 첨부 후 저장 크기
- [ ] 쿠폰 입력 → PREMIUM 전환·기간 가산
- [ ] 만료 배치 (§2 의 절차)

## 8. 알려진 이슈

- **`band_plans` 의 데이터베이스 설명문이 낡았다.** "만료돼도 자동으로 안 내려간다"고
  적혀 있는데 이제 내려간다. 이미 적용된 마이그레이션은 고칠 수 없어서(고치면 앱이
  안 뜬다) 그대로 뒀다. 개발자가 실제로 읽는 코드 주석은 고쳤다.
- **만료 대상을 찾는 조회에 인덱스가 없다.** 밴드당 한 줄이고 하루 한 번 도는 작업이라
  지금 규모에선 문제없다. 밴드가 수만 개가 되면 추가한다.
