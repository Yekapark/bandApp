# 프리미엄 혜택 추가 · 만료 예고 · 앱 문구 정리 (2026-09-06)

## 1. 한 줄 요약

**프리미엄에 "정기 합주 자동 등록"을 넣고, 구독이 끝나기 전에 밴드장에게 미리 알리도록 했다.**
그리고 사용자 화면에 남아 있던 개발자 문구(Firebase·환경변수 이름·개발자 콘솔 지시)를 걷어내고
말투를 `~어요` 체로 통일했다.

## 2. 왜 했나

### 프리미엄이 빈약했다 — 그런데 원인은 다른 데 있었다

지시자가 "프리미엄 권한이 좀 줄어든 느낌"이라고 했는데, 코드를 전수 조사하니 **줄어든 게 아니었다.**
`PlanTier` 를 참조하는 곳은 요금제 패키지 밖에 **단 한 곳**(미디어 보관기한)뿐이고 `BUILD_PLAN` §4.4
설계 그대로다. 처음부터 하나였다.

빈약해 보인 진짜 이유는 **비교표 두 줄 중 하나가 `게시판·일정·정산  제한 없음 / 제한 없음`** 이었다는 것.
차이 없는 항목을 굳이 보여줘서 "혜택이 하나뿐"이라는 인상을 스스로 강조하고 있었다.

### 구독이 조용히 끝나고 사진·영상이 사라진다 — 이게 더 급했다

`PlanExpirationJob` 이 매일 04:45 에 말없이 강등하고, 30일 유예 뒤 첨부가 삭제된다.
**아무에게도 알리지 않았다.** 밴드원 입장에서는 합주 영상이 예고 없이 없어지는 일이라,
문구 문제가 아니라 데이터 사고다. 지시자가 이 지점을 짚었다.

## 3. 무엇을 만들었나

### 3.1 정기 합주 자동 등록을 PREMIUM 으로

없어도 매번 손으로 등록하면 되고, 밴드 단위이며(`/bands/{bandId}/recurring-rules`), 밴드장이 쓰는
기능이라 결제 결정권자와 일치한다 — "있으면 편하지만 없어도 되는" 기준에 맞다.

- 막는 지점은 **규칙 생성 하나뿐**(`RecurringRuleService.create`). 조회·수정·삭제는 그대로
- 요금제 확인은 `PlanDirectoryService.requirePremium(bandId)` — 게시판 미디어가 이미 쓰는 창구다
- FREE 가 시도하면 `PLAN_REQUIRED`(403)

> **이미 만든 규칙과 회차 생성 배치는 건드리지 않는다.** 요금제가 내려가도 다음 회차는 계속 만들어진다.
> 배치까지 멈추면 사용자가 모르는 사이 다음 주 합주가 사라지고, 그건 미디어가 예고 없이 지워지는 것과
> 같은 종류의 사고다. 통합 테스트로 못박아 뒀다.

### 3.2 만료 예고 — 푸시 + 홈 배너

알림 인프라를 그대로 재사용했다. `notification_dispatches.type` 이 `VARCHAR(40)` 이고 CHECK 가
없어 **마이그레이션이 필요 없었다.**

| | |
|---|---|
| `PLAN_EXPIRING_SOON` | 30·7·1일 전. 멱등 키의 `variant` 에 남은 일수를 넣어 시점마다 한 번씩만 |
| `PLAN_EXPIRED` | 강등 직후. 이벤트(`NotificationEvents.PlanExpired`)로 받는다 |
| `PlanExpiryReminderJob` | 매일 04:30 KST. **강등 배치보다 이르게** — 예고가 먼저 나가야 한다 |
| 홈 배너 | 만료 30일 안이면 전원에게. 밴드장에게만 요금제 화면 버튼 |

**받는 사람은 밴드장이다.** 요금제를 바꿀 수 있는 유일한 사람이라, 멤버에게 푸시를 보내면
할 수 있는 게 없는 알림이 된다. 대신 홈 배너는 모두가 본다.

#### 만들다가 테스트에 잡힌 것

처음에는 "30일 안", "7일 안", "1일 안" 을 각각 조회했다. 그랬더니 **6일 남은 밴드가 30일 창과
7일 창에 모두 걸려 알림이 두 번 나갔다.** 테스트가 `expected: 1 but was: 2` 로 잡았다.

밴드마다 남은 일수로 **구간을 하나만** 고르도록 바꿨다(`bucketFor`). 날이 지나면 구간이
30 → 7 → 1 로 옮겨가고 `variant` 가 달라 구간마다 한 번씩만 간다. 배치를 하루 걸러도
다음 실행이 같은 구간을 집어내므로 놓치지 않는다.

### 3.3 앱 문구

- **알림 설정** — "앱 알림 권한과 Firebase 설정이 필요해요 / 발송 준비가 끝나는 대로 적용돼요".
  `Firebase` 는 사용자가 할 수 있는 일이 아니고, **뒷문장은 이제 거짓**이었다(FCM 이 붙기 전에 쓴 글).
  휴대폰 알림 설정 이야기만 남겼다
- **밴드 설정** — `위험한 작업` 섹션 제목 삭제. GitHub *Danger Zone* 직역이었고, 아래 빨간 버튼과
  설명이 이미 그 일을 한다. "영구히 사라집니다" / "영구 삭제됩니다" 중복도 정리
- **지도 안내문** — 4개 분기 중 3개가 개발 지시문이었다(환경변수 이름, 개발자 콘솔, x86 에뮬레이터).
  화면에는 "지도를 지금 불러올 수 없어요" 한 줄만 남기고 원인 구분은 `debugPrint` 로 내렸다
- **요금제 화면** — 차이 없는 비교표 행을 빼고 정기 일정을 넣었다. 구독 다이얼로그에 **1년이라는
  기간과 만료 뒤 무슨 일이 생기는지**를 넣었다(전에는 해지 경로에만 유예 안내가 있었다)
- **말투** — 성공은 `했어요`, 실패는 `못했습니다` 로 갈리던 것을 `~어요` 로 통일(27개 파일)

```bash
./gradlew test --tests '*RecurringPlanGate*' --tests '*PlanExpiryReminder*'
```

```bash
cd C:\band\bandApp\client && flutter test test/copy_tone_test.dart
```

앱에서 보려면 — 설정 > 요금제에서 쿠폰으로 PREMIUM 을 만든 뒤, 캘린더 > 정기 일정에서 등록이
되는지 본다. FREE 로 해지하면 등록 버튼에서 안내가 뜨고, **이미 만든 규칙은 그대로 남는다.**

홈 배너는 만료 30일 안에만 뜬다. 재현하려면 서버에서 만료일을 당긴다:

```sql
UPDATE band_plans SET expires_at = now() + interval '5 days' WHERE band_id = <밴드id>;
```

## 6. 알려진 이슈 / 안 한 것

- **유예 중(만료 직후 30일)에는 홈 배너가 안 뜬다.** 앱이 "방금 강등됨"과 "원래 무료"를 구분할 수
  없어서다 — FREE 의 `startedAt` 은 밴드를 만든 시각이기도 해서, 그걸로 판단하면 **새로 만든 밴드마다
  "프리미엄이 끝났어요"** 가 뜬다. 만료 순간은 `PLAN_EXPIRED` 푸시가 알린다. 유예 중에도 띄우려면
  요금제 응답에 유예 종료 시각을 실어야 한다
- **결제는 여전히 no-op.** PREMIUM 전환은 쿠폰으로만 가능하다
- `V10__plan.sql` 주석의 옛 서술은 그대로 뒀다(적용된 마이그레이션은 건드리지 않는다)
- 지도·정산 모아보기·셋리스트는 프리미엄 후보였으나 이번엔 정기 일정만 선택됐다
