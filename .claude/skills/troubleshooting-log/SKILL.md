# 문제 기록 남기기

문제를 하나 해결할 때마다 `docs/TROUBLESHOOTING.md` **맨 위**(제목·규칙 블록 다음, 기존
첫 항목 앞)에 새 항목을 끼워 넣는다. 코드만 고치고 넘어가지 않는다 — 원인이 코드에 안
보이는 종류가 대부분이라, 기록이 없으면 다음 세션이 똑같이 헤맨다.

## 형식

```markdown
## YYYY-MM-DD — (한 줄 증상 요약, 사용자가 겪은 말로)

**증상** — 무엇이 어떻게 안 됐는지. 실제 에러 메시지·상태코드·화면을 그대로.

**원인** — "무엇이 잘못됐다"에서 멈추지 말고 **"왜 그렇게 됐다"**까지 쓴다.
원인이 둘 이상이면 번호로 나눈다.

**해결** — 무엇을 바꿨는지. 대안을 버린 이유가 있으면 같이.

**확인법** — 고쳐졌음을 **다시 확인할 수 있는 방법**. 명령어·테스트 이름·기대 결과.

---
```

## 쓰는 법

1. 날짜는 오늘 날짜. 같은 날 항목이 이미 있어도 새 `##` 블록으로 따로 쓴다.
2. **네 칸이 다 차야 완성이다.** 확인법이 없으면 그 기록은 다음 사람에게 쓸모가 없다.
3. 원인 쓰기 — 나쁜 예 "플래그를 일찍 세워서" / 좋은 예 "실패할 수 있는 작업 **앞에**
   세워서, 실패한 뒤 재시도가 막혀서".
4. 코드를 안 쓰는 사람도 읽게 쓴다. 파일·줄 번호는 괄호로 덧붙이는 정도.
5. **못 고친 것도 적는다.** "아직 안 고침 — 이러이러해서 우회했다"가 안 적는 것보다 낫다.
6. 확인법에 테스트가 있으면 테스트 이름을 그대로 적는다
   (예: `EmailVerificationIntegrationTest.email_signup_starts_unverified_and_sends_no_code`).

## 하지 말 것

- 기존 항목을 고치거나 지우지 않는다. 틀린 게 있으면 새 항목에서 바로잡고 이전 것을 링크한다.
- 파일 맨 아래에 추가하지 않는다. **최신이 위**다.
