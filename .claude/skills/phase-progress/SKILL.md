# Phase 진행 기록 쓰기

`docs/progress/phase-NN-<주제>.md` 를 새로 만들고, 다 쓴 뒤 `docs/progress/README.md` 의
문서 목록 표에 줄을 추가/갱신한다.

**목표 독자: 코드를 직접 쓰지 않고 작업을 지시하는 사람.** 개발 배경지식 없이도
"무엇을 / 왜 / 어떻게 확인하는지"가 이해되어야 한다. 클라이언트 작업이면
`client-NN-<주제>.md` 로 하고 `client-DEVLOG.md` 도 같이 갱신한다.

## 목차 (9절 고정)

1. **한 줄 요약**
2. **이 Phase의 목표** — `BUILD_PLAN.md` 의 해당 Phase 기준을 그대로 옮긴다
3. **무엇을 만들었나** — 파일/구성요소별로 *존재 이유*와 함께. 파일 목록만 나열하지 않는다
4. **어떻게 동작하나** — 요청부터 응답까지 흐름을 말로
5. **직접 확인하는 법** — 사전 준비 / 명령어 / **기대 결과** / 안 될 때 확인할 것.
   지시자가 이 절만 보고 혼자 돌려볼 수 있어야 한다
6. **실제 검증 기록** — 무엇을 돌렸고 결과가 무엇이었는지. 돌린 적 없으면 "안 돌림"이라 쓴다
7. **알려진 이슈 / 제약** — 못 한 것, 우회한 것, 다음으로 미룬 것
8. **커밋 · CI 링크** — PR 번호와 링크
9. **다음 Phase 예고**

## 규칙

- **5절이 이 문서의 핵심이다.** 명령어만 적고 기대 결과를 빼면 확인이 안 된다.
- 6절에 "통과했다"만 쓰지 않는다. 무엇을 어떤 환경에서 돌렸는지(로컬 compose / CI /
  실기기)를 적는다. 로컬에서 `./gradlew test` 가 안 도는 환경이면 그 사실도 적는다.
- 7절을 비우지 않는다. 완벽한 Phase는 없다. 빌 것 같으면 덜 판 것이다.
- 다 쓰면 `README.md` 표에 한 줄 — Phase 번호 / 문서 링크 + 핵심 내용 요약 / 상태
  (`✅ 완료 — CI 통과 (PR #NN)` 형식).
- 못 끝낸 것이 있으면 `docs/progress/NEXT.md` 에도 옮겨 적는다.
